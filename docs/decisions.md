# 결정 기록

이 문서는 dotfiles의 에이전트 설정(전역 지침, 스킬, 워크플로우)을 두고 내린 결정과 그 이유를 모은다. 같은 논의를 다시 하지 않도록, 코드와 git 이력만으로는 알 수 없는 "왜"와 "기각한 대안"을 남긴다.

판단 기준이 되는 원칙은 [`VISION.md`](../VISION.md)에 있다. 앞으로 할 일은 [`backlog.md`](backlog.md)에 적는다.

## 쓰는 법

- 결정마다 **결정**, **이유**, **기각한 대안**을 적는다. 조건이 바뀌면 다시 볼 결정에는 **다시 볼 조건**을 덧붙인다.
- 결과물이 남지 않은 결정(하지 않기로 한 것)도 적는다.
- 커밋 메시지에 들어갈 만큼 작은 이유는 커밋 메시지에 적고 여기에는 적지 않는다.
- 새 결정은 날짜 절을 만들어 위에 추가한다. 뒤집힌 결정은 지우지 않고, 새 결정에서 어느 결정을 대체하는지 밝힌다.

## 2026-11-20 독립 검토 반영

같은 날의 정리 결과를 Codex(GPT-6.2 Astra)에 읽기 전용으로 검토시켰다. 검토는 두 번 했다. 첫 번째는 결정 자체를, 두 번째는 중복·간결함·명확함을 물었다. 지적 가운데 네 가지를 직접 확인했고 모두 사실이었다. 아래 결정은 바로 다음 절의 일부 결정을 대체한다.

### 서드파티 스킬은 `grilling`과 `teach`만 남긴다

- **결정**: `wait-what`, `prototype`, `retro`, `writing-for-agents`를 뺀다. "Matt 스킬을 6개로 줄인다"와 "`skillOverrides`에 한 줄만 둔다"를 대체한다. `skillOverrides`는 다시 비었다.
- **이유**:
  - `wait-what`: 본문이 "Simplified Technical English로, `GLOSSARY.md`의 용어로 다시 설명하라"이다. 한국어로 다시 설명받는 용도와 맞지 않고, 용어집을 기본으로 만들지 않는 방침과 어긋난다.
  - `prototype`: 마지막 규칙이 시안을 별도 브랜치에 커밋하고 이슈에 포인터를 남기라고 한다. `ui-improve`가 시안을 보려고 부르기만 해도 커밋과 이슈 갱신이 따라온다.
  - `retro`: 본문이 Claude 전용 도구 이름으로 `writing-for-agents`를 부른다. Codex에는 그 도구가 없다.
  - `writing-for-agents`: Codex에서는 자작 `skill-writer`와 함께 설명 전체가 노출되어 같은 요청에 경쟁한다. Claude에서만 `name-only`로 풀어 둔 상태였다.
- **대신 한 것**:
  - `prototype`의 쓸 만한 부분(실제 페이지 안에 서로 뚜렷이 다른 시안을 만들고, 고른 뒤 나머지를 지운다)을 `ui-improve`에 넣었다.
  - 회고는 목적 자체가 필요해서 자작 `retro`로 새로 썼다. 원인에 가장 가까운 곳(검사, 스크립트, 스킬, 레포 지침, 전역 지침 순)을 고치게 했고, 지침을 지우는 것도 수정으로 본다.
- **기각한 대안**: `grill-with-docs`와 `domain-modeling`을 다시 넣는 것. 결정은 이제 전역 규칙에 따라 `docs/decisions.md`에 남으므로 ADR 자동 생성과 역할이 겹친다. 용어 때문에 설계가 갈리는 레포가 생기면 그 레포에만 넣는다.
- **나중에 참고할 것**: `wait-what`의 요령(맥락을 먼저 주고, 짧은 문장으로, 같은 것은 같은 단어로 다시 설명한다)은 전역 Reporting 규칙에 이미 있다. 워크플로우 스킬 `orient`를 고칠 때 "돌아온 사람에게 다시 설명한다"는 부분에 참고한다.

### 코드 소유권 지침은 머신이 아니라 레포에 둔다

- **결정**: Mac 전역 추가 지침을 없애고, 소유권 문단을 개인 레포의 `AGENTS.md`에 직접 넣는다. 이 레포에 먼저 넣었다. 설계 선호(검색으로 찾을 수 있는 이름, 한곳에 모인 동작, 검사로 강제하는 제약)는 전역 지침의 Code 절에 남긴다. "코드 소유권 지침은 개인용 Mac에만 넣는다"를 대체한다.
- **이유**:
  - `machines.toml`의 `[local]`은 "개인 Mac"이 아니라 "이름 없이 적용한 모든 머신"이다.
  - 소유권이 맞는지는 머신이 아니라 레포의 성격이다. 같은 Mac에서 회사 레포도 연다.
  - 머신 전역에 두면 회사 레포마다 "최소 변경"을 적어야 해서 유지 비용이 반대쪽에 걸린다.
- **기각한 대안**: 머신에 개인용·회사용 구분자를 추가하는 것. 한 머신에 두 종류의 레포가 섞여 있어서 구분자가 문제를 풀지 못한다.
- **다른 개인 레포에 넣을 때**: 이 레포 `AGENTS.md`의 "Code ownership" 문단을 복사한다.

### 스킬과 문서의 중복을 줄인다

- **결정**: 보고 순서, 미확인 항목 표시, 저장 경로, 읽기 전용 레포에 쓰지 않는다는 규칙은 전역 지침에만 둔다. 스킬에는 그 작업에만 있는 산출물과 검사만 남긴다.
- **이유**: 같은 문장이 스킬 열한 곳과 전역 지침에 있었다. 한 곳을 고치면 나머지가 어긋난다.
- **남긴 반복**: 서브에이전트에게 단독으로 넘기는 브리프 파일은 본문 규칙을 짧게 반복한다. 브리프만 받는 실행자가 있기 때문이다.
- **기각한 대안**: `youtube-transcript`가 질문 하나에도 전사를 저장한다는 지적. 전사 파일이 이 스킬의 산출물이라 기본 저장을 유지한다.

### 전역 지침에서 고친 문장

- "검사가 통과하면 멈춘다"는 작업을 멈추라는 뜻으로 읽힐 수 있어서 "검증을 멈추고 남은 작업을 계속한다"로 고쳤다.
- 새 맥락의 독자는 "작성자의 맥락이 없다는 점이 검사 목적일 때"로 좁혔다. "diff 리뷰"를 예로 들면 평범한 diff마다 리뷰어를 부르는 근거가 된다.
- 언어 규칙에 "기존 문서는 그 문서의 언어를 따른다"를 넣었다. 영어 오픈소스 README의 한 문장을 고치는 경우가 예다.
- 결정 기록의 기준을 "채택된 결정이고, 뒤의 작업을 제약하며, 이유가 다른 곳에 없을 때"로 좁혔다.
- 테스트 추가 조건에 "기존 검사가 보호하지 못하는 새 계약"을 넣었다.

### `improve-structure`의 계약을 고친다

- **결정**: 발견한 결함은 고치지 않고 재현 방법과 함께 보고한다. 얕은 테스트는 새 테스트가 같은 실패를 잡을 때만 지운다. 쉬워지는 변경을 구체적으로 댈 수 없으면 코드를 그대로 두는 것도 올바른 결과로 인정한다.
- **이유**: "동작은 그대로"라는 완료 조건과 "발견한 결함을 고친다"가 서로 어긋났다. 장난감 레포 한 번의 시험으로는 합치면 안 될 때 멈추는지를 확인하지 못했다.

### 스킬 검사기를 보강한다

- **결정**: `check_skill.py`가 따옴표 없는 frontmatter 값 안의 `: `와 ` #`를 오류로 잡는다.
- **이유**: `youtube-transcript`의 설명이 엄격한 YAML 파서에서 실패하는데 검사기는 통과시켰다. 두 도구의 현재 로더는 받아 주지만 공용 검사기가 유효하다고 보증하면 안 된다.

## 2026-11-20 에이전트 설정 정리

Claude Fable 5.2, Claude Opus 5.5, GPT-6.2의 공식 프롬프트 가이드와 두 회사의 개발자 블로그를 읽고 설정 전체를 다시 맞췄다. 근거로 읽은 자료 목록은 `VISION.md`의 Sources 절에 있다.

### Matt Pocock 스킬을 27개에서 6개로 줄인다

- **결정**: `grilling`, `prototype`, `retro`, `teach`, `wait-what`, `writing-for-agents`만 남긴다.
- **이유**:
  - 9월 이후 Claude Code 세션 358개에서 실제로 쓴 Matt 스킬은 grill 계열과 `domain-modeling`뿐이었다.
  - 자작 스킬과 충돌하는 스킬이 있었다. `research`는 `workflow-research`와, `code-review`는 내장 `code-review`와 같은 요청에 반응했다. `domain-modeling`과 이슈 트래커 계열 8개는 "다른 원천에서 복원할 수 없는 것만 문서로 남긴다"는 워크플로우 방침과 어긋났다.
  - 최신 모델 가이드는 이전 모델용으로 쓴 처방적인 스킬이 결과를 떨어뜨릴 수 있으니 빼고 비교하라고 한다.
- **기각한 대안**:
  - `diagnosing-bugs`: 6단계 고정 절차, 압박 문구, 고정 개수가 가이드가 지적하는 패턴 그대로다. "뭔가 고장났다"는 말에 자동으로 켜져 작은 버그에도 무거운 절차가 걸린다. 쓸 만한 핵심인 "고치기 전에 실패를 재현한다"는 전역 지침의 Verification 절로 옮겼다.
  - `implement`: `tdd`, `code-review`, 이슈 트래커를 잇는 17줄짜리 연결 스킬이다. 그 셋을 빼면 모델의 기본 동작만 남는다.
  - `improve-codebase-architecture`: 원하는 형태는 "후보 보고와 인터뷰 없이 고치고 끝에 결과를 보고한다"인데, 이 스킬의 3단계 중 HTML 보고서와 인터뷰 2단계를 버려야 한다. 업스트림 파일은 고쳐도 덮어써지므로 자작 `improve-structure`로 대체했다.
  - `grill-me`, `grill-with-docs`: `grill-me`는 `grilling`을 부르는 한 줄짜리 래퍼라 `/grilling`으로 대신한다. `grill-with-docs`는 용어집과 ADR을 자동으로 만드는 기능이 필요 없어서 뺐다.

### Matt 스킬은 플러그인이 아니라 매니페스트로 설치한다

- **결정**: `config/ai/skills-manifest.toml`에 6개를 선언하고 `npx skills`로 Claude Code와 Codex에 함께 설치한다. Claude 플러그인 `mattpocock-skills`는 끈다.
- **이유**:
  - Claude 플러그인은 스킬 27개를 통째로만 켜고 끌 수 있다.
  - `skillOverrides`는 플러그인 스킬에 적용되지 않는다(Claude Code 문서: "Overrides don't apply to plugin skills").
  - 두 도구가 같은 방식으로 같은 스킬을 받고, 매니페스트에서 빠진 스킬은 설치 스크립트가 지운다.
- **기각한 대안**: 6개를 `config/ai/skills/`로 복사해 자작으로 관리하는 방식. 내용을 고칠 수 있지만 자주 바뀌는 업스트림을 직접 따라가야 한다. 지금은 고칠 것이 없다.
- **다시 볼 조건**: 스킬 내용을 고치고 싶거나 업스트림 변경이 마음에 들지 않으면, 그 스킬만 복사해 자작으로 돌린다.

### `skillOverrides`는 비우고 한 줄만 둔다

- **결정**: 예전 항목을 모두 지우고 `writing-for-agents: name-only` 하나만 둔다.
- **이유**:
  - 예전 항목은 없어진 스킬을 가리키거나, 스킬 frontmatter의 `disable-model-invocation`과 어긋나 있었다.
  - `writing-for-agents`는 자작 `skill-writer`와 "스킬 만들어줘"에서 겹친다. 그런데 `retro`가 첫 단계에서 이 스킬을 부르므로 완전히 끌 수 없다. `name-only`는 설명만 숨기고 호출은 허용한다.
- **알아 둘 점**: 직접 호출 전용(`disable-model-invocation: true`) 스킬은 사용자 메시지에 `/이름`이 있을 때만 실행되므로, 다른 스킬이 부를 수 없다.

### 자작 스킬은 지우지 않는다

- **결정**: 자작 스킬 중 삭제한 것은 없고, `improve-structure`를 추가했다.
- **이유**: 서로 겹치는 쌍이 없다. 사용 기록이 없는 스킬도 대부분 직접 호출 전용이라 평소 비용이 없다.

### 전역 지침에 검증, 보고, 문서 규칙을 둔다

- **결정**: `config/ai/AGENTS.md`에 Verification, Reporting, Files and documents 절과 "사용자 지시가 스킬보다 우선한다"를 넣는다.
- **이유**:
  - 보고 규칙이 스킬 10여 개에 흩어져 있었고, 검증 규칙은 워크플로우를 설치한 레포에만 있었다. 전역에 두면 두 도구와 모든 프로젝트에 똑같이 적용된다.
  - "지칭이 애매하다"는 실제 불편이 있어서 Reporting에 "같은 것은 같은 단어로 부르고, 가리키는 대상이 둘일 수 있으면 이름을 다시 쓴다"를 넣었다.
- **세부 결정**:
  - **새 맥락 리뷰는 허용한다.** 처음에는 "자기 작업을 서브에이전트로 재확인하지 않는다"로 썼다가 고쳤다. Claude Code 팀은 새 맥락 에이전트의 diff 리뷰를 실제로 쓰고, 경계하는 것은 확인 단계를 겹쳐 쌓는 것이다.
  - **버그 수정은 실패를 먼저 재현한다.** 절차가 아니라 완료 기준이라서 넣었다. 실제로 실패를 본 적 없이 넣은 유일한 규칙이므로, 불필요하면 가장 먼저 뺀다.
  - **"Finishing work" 문단은 넣지 않는다.** Anthropic이 권하는 문단인데 출력 토큰이 약 30% 늘어난다. 중간에 멈추는 일이 실제로 보이면 넣는다.

### 문서는 독자에 따라 나눠서 쓴다

- **결정**: 문서를 쓰는 조건을 독자별로 나눠 전역 지침의 Files and documents 절에 둔다. 규칙 본문은 그 절이 기준이다.
- **이유**: 채팅으로 충분한 내용을 스킬이 문서로 저장하는 일이 반복됐다. 반대로 결정의 이유는 어디에도 남지 않아 다시 논의하게 된다.
- **기각한 대안**:
  - "다음 세션으로 넘어가야 할 때 문서를 쓴다"는 조건. 다음 세션의 독자는 대개 에이전트라서 인계 문서를 만드는 구실이 된다.
  - "새 문서보다 기존 문서를 고친다"는 문장. 실제로 문제가 된 적이 없는 규칙이라 뺐다.
  - `ko-tech-writing`을 `writing-for-human`으로 바꾸는 것. 한국어 규칙이 이 스킬의 실제 내용이라 지금 이름이 더 정확하다. 에이전트용 문서는 `writing-for-agents`와 `skill-writer`가 맡는다.

### 에이전트용 지침은 영어로 쓴다

- **결정**: AGENTS.md, 스킬, 그 참조 파일은 영어로 쓴다. 사용자에게 하는 말과 사람용 문서는 한국어로 쓴다.
- **남은 것**: 워크플로우 프로토콜이 레포에 심는 AGENTS 블록은 아직 한국어다. `agent-workflow-protocol` 레포에서 고쳐야 한다.

### 코드 소유권 지침은 개인용 Mac에만 넣는다

- **결정**: "이 코드베이스의 소유자이자 장기 유지보수자"라는 지침을 `config/ai/agents-additions/personal-machine.md`에 두고 `machines.toml`의 `[local]`에만 연결한다. 원격 서버에는 넣지 않는다.
- **이유**:
  - 사람이 코드를 줄 단위로 읽는 일이 줄었으므로, 코드는 에이전트가 유지보수하기 좋게 짜는 편이 낫다. 실제로 달라지는 것은 세 가지다: 검색으로 찾을 수 있는 이름, 한곳에 모인 동작, 산문 대신 검사(타입, 테스트, 린트)로 강제하는 제약.
  - Anthropic 가이드는 이 문장을 상황에 따라 쓰라고 한다. 넣으면 모델이 스스로 구조를 정리하지만, 출력 토큰이 1.7–1.8배가 되고 요청하지 않은 변경이 섞인다. 사용자가 코드를 최소한으로 바꾸길 원하는 곳에서는 빼라고 한다.
- **안전장치**: 요청 밖에서 바꾼 것은 작은 것까지 보고에 적게 했다. 레포 자체 지침과 "최소한으로 바꿔 달라"는 요청이 이 지침보다 우선한다.
- **알아 둘 점**: Mac에서 여는 모든 레포에 적용된다. 회사 레포를 Mac에서 열 때는 그 레포의 `AGENTS.md`에 최소 변경을 적는다.

### 스킬 문구에서 고친 방향

- **결정**: 자작 스킬에서 "가능하면 서브에이전트에 맡긴다"를 "언제 위임이 값어치가 있는지"로 바꾸고, 근거 없는 고정 개수("3 to 5" 등)를 지웠다. `skill-writer`가 같은 방향으로 새 스킬을 만들도록 고쳤다.
- **이유**: 두 회사의 가이드 모두 위임을 권하는 상시 문구를 먼저 재검토하라고 한다. 최신 모델은 지시를 문자 그대로 따르므로 "가능하면"은 "항상"처럼 동작한다.

### 모델 설정

- **결정**: Codex는 `gpt-6.2-sol`, Claude Code의 기본 모델은 `opus`로 둔다. 조사용 서브에이전트도 Opus로 돌린다.

### `VISION.md`는 레포 최상위에 둔다

- **결정**: 원칙 문서를 `config/ai/`가 아니라 `dotfiles/VISION.md`에 둔다.
- **이유**: 어느 도구에도 배포되지 않는 문서이고, 스킬과 지침을 고칠 때 기준으로 삼는 이 레포의 원리다. 워크플로우 스킬 `orient`가 찾는 이름이 `VISION.md`라서 단수로 맞췄다.
- **알아 둘 점**: `dotfiles`는 public 레포라서 이 문서와 결정 기록은 공개된다.

### 점검 결과로 남기는 것

- Claude Code의 `/doctor prompt-audit`을 돌렸다. 강조 대문자나 "think step by step" 같은 낡은 패턴과 지침 파일 간 충돌은 없었다. 걸린 것은 낡은 경로 1건과 위임 문구 5건이었고 모두 고쳤다.
- 모델이 바뀔 때마다 이 점검을 다시 돌린다. 한 세대에서 필요했던 문구가 다음 세대에서는 방해가 된다.

- 레포에 심는 AGENTS 블록 12줄에서 전역으로 옮긴 검증·보고 줄과 모델 기본 동작과 겹치는 줄을 빼 8줄로 줄인다.
- `orient`, `align`, `workflow-research`, `cold-read`의 설명에 언제 쓰는지와 경계를 보강한다.
- AGENTS 블록을 영어로 옮긴다.
- `workflow-research`의 "결정에 쓰이면 synthesis를 남긴다"와 `align`의 "다음 세션으로 넘길 때 문서를 쓴다"를 새 문서 규칙에 맞춘다.
- 프로토콜 원본(`P-0042`)이 dotfiles에 배포된 사본(`P-0033`)보다 앞서 있다. 원본에는 "사용자 지시 > 스킬 > AGENTS.md 순으로 따른다"와 "subagent의 완료 주장은 재확인한다"가 있어, 그대로 배포하면 이번에 정리한 방향과 어긋난다. 배포 전에 조정한다.

dotfiles 프레임워크에서 해야 하는 일이다.
